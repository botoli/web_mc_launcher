# Веб-приложение

Next.js / React / TypeScript. Все npm-команды выполняются из корня репозитория: `npm run dev`, `npm run build`, `npm start`, `npm run typecheck`.

- `app/` — маршруты, layout и общие стили.
- `components/` — формы, таблицы, навигация и компоненты интерфейса.
- `lib/` — типы и клиенты API для браузера и серверного рендеринга.
- `next.config.ts` — настройки Next.js и проксирование запросов к API.

Открывайте публичный адрес Express (по умолчанию `http://localhost:3000`). Общий runner запускает Next.js на внутреннем порту и передаёт ему адрес API и окружение из корневого `.env`.

Страницы входа и регистрации формируют HTML формы на сервере; параметры URL передаются из страницы в компонент формы. Не оборачивайте всю форму в клиентский `useSearchParams`/`Suspense`: при сбое JavaScript это оставляет пользователя на «Загрузка…». Нативные POST-формы `/api/web-auth/login` и `/api/web-auth/register` обеспечивают вход и регистрацию без скриптов, сохраняя cookie и изменения в транзакции API. Существующие `/api/auth` и `/api/register` возвращают JSON для лаунчера и браузерного клиента.

Игроки и первая страница логов также загружаются на сервере и входят в исходный HTML, включая фильтры из URL. Не добавляйте `loading.tsx` вокруг этих страниц: потоковый fallback требует JavaScript для раскрытия готового HTML и может оставить таблицы скрытыми при заблокированных скриптах. Основные разделы открываются обычными ссылками; анимация перехода не пересоздаёт содержимое страницы. Анимации загрузки используются в навигации и при обновлении таблиц. Браузерные запросы ограничены 20 секундами (загрузка файлов — 10 минутами), внутренние обращения Next.js к API — 10 секундами.

В конфигурации Nginx `/_next/static/` обслуживается напрямую с долгим кэшем по хэшированным URL; HTTPS поддерживает HTTP/2. При обновлении сборки сохраняйте предыдущие статические файлы для уже открытых вкладок.
