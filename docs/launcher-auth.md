# Telegram: контракт для разработчика лаунчера

## Сценарий

1. Нажатие «Войти через Telegram» создаёт запрос на backend.
2. Лаунчер показывает полученный `code` и таймер до `expires_at`, открывает `url` в Telegram. Рядом стоит оставить кнопку «Открыть бота» для повторного открытия. Код остаётся видимым в лаунчере; передавать его в параметре `start` не нужно.
3. Бот просит вручную отправить код из лаунчера. Если ссылка не открылась, игрок может открыть бота сам, нажать «Привязать лаунчер» (у уже привязанного — «Войти в лаунчер») и отправить этот же код. Без кода регистрация и привязка в боте недоступны: стартовый экран предлагает скачать лаунчер с публичного адреса проекта. Старые `/register`, `/link` и кнопки возвращают эту инструкцию.
4. Для Telegram без привязки после проверки кода бот просит ник. Для существующего непривязанного аккаунта нужно ввести его пароль; для свободного ника — задать и повторить новый пароль. Если ник не найден, бот предупреждает о возможной опечатке и оставляет «Ошибка в нике?» и «Отмена» на шагах пароля и подтверждения. «Ошибка в нике?» открывает выбор без сброса данных: «Продолжить с этим ником» возвращает к прежнему шагу, «Ввести ник заново» сбрасывает пароль и возвращает `step` к `awaiting_nickname`, сохраняя первоначальный `expires_at`. Пока открыт выбор, `step` сохраняет прежнее значение. Отмена закрывает запрос со статусом `cancelled`. Подтверждение кнопкой обязательно: до него аккаунт не создаётся и Telegram не привязывается. Занятый другим Telegram ник и заблокированный аккаунт использовать нельзя. Если привязка уже есть, ник повторно не запрашивается.
5. Лаунчер опрашивает статус. При `confirmed` один раз обменивает запрос на сессию, сохраняет токен в защищённом локальном хранилище и показывает `user.nickname`.

Обновлять нужно backend (`apps/api/`) и отдельно развёрнутый worker (`apps/bot/`), затем перезапустить оба процесса. Новых переменных окружения нет. Бот должен хотя бы один раз подключиться к backend, иначе создание запроса вернёт `503`.

## 1. Создать запрос

```http
POST /api/auth/telegram/challenges
Content-Type: application/json

{}
```

Пример ответа `200`:

```json
{
  "id": "<идентификатор запроса>",
  "poll_secret": "<секрет опроса>",
  "code": "A1B2C3D4",
  "expires_at": 1792000300000,
  "url": "https://t.me/YourBot?start=<параметр ссылки>"
}
```

`expires_at` — Unix time в **миллисекундах**; запрос действует 5 минут. Код теперь содержит **8** символов `0–9`, `A–F`: уберите ограничение интерфейса на 6 символов. При желании показывайте `A1B2-C3D4`: бот принимает дефис, пробелы и любой регистр. Поле `url` нужно использовать целиком, не собирать вручную. Оно не содержит секрета опроса и не заменяет код.

`id` и `poll_secret` храните в памяти текущего окна входа. Не публикуйте `poll_secret` в Telegram, логах и URL. Ответы с секретами помечены `Cache-Control: no-store`.

Ошибки: `503` — бот не настроен/ещё не подключён; `429` — слишком много запросов (в том числе более 5 активных на сетевой адрес). При `429` остановите частые повторы и предложите повторить позже.

## 2. Опрос статуса

```http
GET /api/auth/telegram/challenges/<id>
X-Poll-Secret: <poll_secret>
```

Ответ `200`:

```json
{
  "status": "pending",
  "step": "awaiting_nickname",
  "expires_at": 1792000300000
}
```

Опрос раз в **2 секунды**. Основная логика должна опираться на `status`; `step` нужен только для подсказки.

| `status` | Действие лаунчера |
|---|---|
| `pending` | Продолжать опрос до таймера |
| `confirmed` | Остановить опрос, выполнить обмен |
| `rejected` | Остановить опрос, показать «Вход отклонён» и повтор |
| `cancelled` | Остановить опрос, показать «Вход отменён» и повтор |
| `expired` | Остановить опрос, предложить новый код |
| `consumed` | Обмен уже выполнен; повторный обмен не выдаст токен |

| `step` при `pending` | Подсказка |
|---|---|
| `awaiting_code` | «Отправьте боту код с этого экрана» |
| `awaiting_nickname` | «Введите игровой ник в Telegram» |
| `awaiting_password` | «Введите или задайте пароль в Telegram» |
| `awaiting_confirmation` | «Подтвердите вход кнопкой в Telegram» |

Для конечных статусов `step` равен `status`. `404` означает неизвестный запрос, неверный секрет или уже удалённый запрос: остановите опрос и начните новый вход. При сетевой ошибке можно повторять опрос до истечения срока. Закрывая окно или начиная новый вход, отмените предыдущий запрос.

## 3. Однократный обмен

```http
POST /api/auth/telegram/challenges/<id>/exchange
X-Poll-Secret: <poll_secret>
Content-Type: application/json

{}
```

Ответ `200`:

```json
{
  "token": "<непрозрачный токен сессии>",
  "expires_at": 1794592000000,
  "user": {
    "login": "existing_login_or_tg_123456789",
    "nickname": "Player",
    "registrationStatus": "pending"
  }
}
```

`token` — **не JWT**, разбирать его не нужно. Сессия действует 30 дней. Сохраняйте токен вместе с URL backend и сроком в защищённом хранилище ОС; игровой ник берите из ответа сервера. `pending` допускает вход.

Не запускайте несколько обменов параллельно. `409` — запрос ещё не подтверждён, отменён, истёк или уже использован; `403` — аккаунт заблокирован/некорректен либо Telegram-привязка изменилась; `404` — запрос/секрет не найден. После успешного обмена повторный обмен не вернёт токен. Если ответ обмена потерялся в сети, потребуется новый вход.

## 4. Проверка сессии и выход

```http
GET /api/auth/me
Authorization: Bearer <token>
```

`200` возвращает `{ "login", "nickname", "registrationStatus" }`. Проверяйте при запуске лаунчера и перед запуском игры. `401` — удалить сохранённую Telegram-сессию и предложить войти заново. Сетевую ошибку показывайте как недоступность сервера; она сама по себе не означает отзыв токена.

```http
POST /api/auth/logout
Authorization: Bearer <token>
Content-Type: application/json

{}
```

Выход отзывает текущую сессию и возвращает `{ "success": true }`. Локальную сессию удалите и при сетевой ошибке, но сообщите, что серверный отзыв не подтверждён.

Для отмены окна входа:

```http
DELETE /api/auth/telegram/challenges/<id>
X-Poll-Secret: <poll_secret>
```

Ответ `{ "success": true }`. Отмена закрывает возможность обмена, но не удаляет аккаунт и уже подтверждённую привязку.

## Привязка и отвязка в боте

Отдельные API для лаунчера не нужны: «Привязать лаунчер» и «Отвязать» работают в боте. Привязка выполняется только внутри запроса с проверенным кодом. Отвязка требует кнопки подтверждения, сохраняет запись аккаунта и отзывает **все Telegram-сессии** этого аккаунта, включая сессии других устройств. Необменённые запросы отменяются. После повторной привязки старые токены остаются недействительными. Парольные launcher-сессии тоже отзываются; web-сессии и уже работающая игра не завершаются.

Один Telegram может иметь один аккаунт. После отвязки можно выбрать прежний или другой ник; при повторном выборе прежнего ника используется прежняя запись. Для заблокированных аккаунтов самостоятельная отвязка запрещена.

Привязка непривязанного аккаунта требует **действующий пароль**. Для старого аккаунта без пароля и без привязки требуется восстановление через администратора. Уже привязанный пользователь может задать пароль из кабинета. Смена пароля отзывает все launcher- и web-сессии; завершение сессий из кабинета отзывает launcher-сессии. После этого проверка старого токена возвращает `401`.

Токен BotFather и `TELEGRAM_BOT_SECRET` в лаунчер не включать. Все запросы в рабочей среде отправлять по HTTPS.


## Журнал входов

Сервер записывает вход по паролю/токену в лаунчер и вход через Telegram, его источник и назначение (`launcher`), IP запроса, Telegram ID, юзернейм и имя бота. Отдельная отправка событий из клиента не нужна. Просмотры конфигурации, проверки сессии и внутренние действия лаунчера не логируются.
