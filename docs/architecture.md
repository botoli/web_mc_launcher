# Структура репозитория

Три приложения находятся в `apps/`, общие команды запуска — в `scripts/`, инструкции — в `docs/`. Один `package.json` и `package-lock.json` в корне управляют зависимостями API и веб-интерфейса. Worker бота использует только встроенные модули Node.js и может работать на другом сервере.

## Где редактировать

| Задача | Каталог или файл |
| --- | --- |
| Страницы, маршруты, layout, общие стили сайта | `apps/web/app/` |
| Компоненты и формы сайта | `apps/web/components/` |
| Типы, браузерные и серверные запросы к API | `apps/web/lib/` |
| Конфигурация Next.js и TypeScript | `apps/web/next.config.ts`, `apps/web/tsconfig.json` |
| HTTP API, cookie/JWT, файлы модов, proxy к Next.js | `apps/api/src/server.js` |
| Пароли и совместимость старых хешей | `apps/api/src/auth/passwords.js` |
| Профили, роли, модерация и журнал | `apps/api/src/players/services.js` |
| Telegram-коды входа, сессии и внутренние API worker | `apps/api/src/telegram/auth.js` |
| Меню, тексты, кнопки, регистрация, привязка и кабинет бота | `apps/api/src/telegram/cabinet.js` |
| Long polling Telegram, отправка/редактирование/удаление сообщений, подтверждения доставки | `apps/bot/bot.js` |
| Таблицы, индексы и транзакции PostgreSQL | `apps/api/src/database/` |
| Расположение корня и файлов данных | `apps/api/src/config/paths.js` |
| Общий запуск API и Next.js | `scripts/run.js` |
| Импорт JSON и резервные копии PostgreSQL | `scripts/db/` |
| Тесты, временные данные и изолированные схемы | `tests/` |
| Systemd-службы | `deploy/` |

## Как связаны приложения

Браузер и лаунчер обращаются к публичному Express API на `PORT` (по умолчанию 3000). Express обслуживает API и файлы, а страницы и WebSocket передаёт в Next.js на `127.0.0.1:FRONTEND_PORT` (по умолчанию 3001). Next.js при серверном рендеринге запрашивает API через `BACKEND_URL`.

Telegram worker обращается к Telegram Bot API и внутреннему API Express через `AUTH_API_URL` с `TELEGRAM_BOT_SECRET`. Сценарии диалогов и проверки прав выполняются в `apps/api/src/telegram/`; worker доставляет обновления и ответы. Изменение меню обычно требует редактирования `telegram/cabinet.js`, а изменение транспорта — `apps/bot/bot.js`. Пользователи, сессии и журнал хранятся на backend в PostgreSQL.

## Запуск и проверка

Все npm-команды выполняются из корня репозитория:

```sh
npm ci
npm run dev             # API + Next.js с обновлением при разработке
npm run build           # Production-сборка apps/web/.next
npm start               # API + собранный Next.js
npm run start:backend   # Только API
npm run start:bot       # Только worker бота; нужен Node.js 22+
npm run typecheck
npm test
```

Для тестов нужны локальные порты, PostgreSQL и установленный Chromium Playwright. Тесты используют временные копии API с той же структурой каталогов и отдельные схемы `mc_test_*`. `TEST_DATABASE_URL` позволяет указать отдельную тестовую базу. Перед `npm test` нужно выполнить `npm run build`.

Обслуживание базы: `npm run db:migrate`, `npm run db:verify`, `npm run db:backup`. Подробнее — [PostgreSQL](database.md). Настройка worker и его самостоятельный запуск — [инструкция бота](../apps/bot/README.md). API Telegram-входа для лаунчера — [контракт](launcher-auth.md).

## Конфигурация, данные и совместимость

Корневой `.env` используется API и общим runner. В `data/` остаются моды, файлы клиентов, сертификаты, исходные JSON и резервные копии. Эти пути вычисляются относительно корня репозитория, поэтому запуск API из другого рабочего каталога не создаёт новую папку данных рядом с исходниками.

Для новой установки worker настройки находятся в `apps/bot/.env`, а неподтверждённые доставки — в `apps/bot/.delivery-receipts.json`. Образцы окружения: [общий](../.env.example) и [для бота](../apps/bot/.env.example). В существующей установке при наличии `bot/.env` используются именно он и соседний файл подтверждений доставки. Старый `.env` имеет приоритет; при переносе остановите worker и перемещайте настройки и подтверждения вместе. `TELEGRAM_DELIVERY_STATE_FILE` по-прежнему задаёт отдельный путь.

`server.js` и `bot/bot.js` в корне — короткие совместимые точки запуска, передающие управление в `apps/`. Весь рабочий код редактируется в `apps/`. Прежние команды `node server.js`, `node bot/bot.js` и существующие systemd-службы продолжают находить приложения.

`frontend` — ссылка на `apps/web`, сохраняющая доступ по прежнему пути для существующих процессов и инструментов. Основные команды используют `apps/web` напрямую. На системах без поддержки символических ссылок используйте новый путь; сборка и запуск от ссылки не зависят.

После обновления исходников выполните `npm run build`, чтобы пересоздать Next.js-сборку в новом каталоге, затем перезапустите свои процессы обычным способом. Новые шаблоны systemd в `deploy/` указывают на актуальные пути; если заменяете установленные unit-файлы, выполните `systemctl daemon-reload` перед перезапуском. Само перемещение исходников не требует повторного импорта базы.
