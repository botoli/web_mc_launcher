# Обновления Windows-лаунчера

Администратор на странице «Сборка» загружает ZIP и указывает версию в формате `MAJOR.MINOR.PATCH` (например, `0.1.1`). Допускается суффикс предварительного выпуска, например `0.1.1-beta.1`. ZIP должен содержать ровно два файла в корне: `Nevermore` и `README.txt`. Максимальный размер архива — 500 МБ. Сервер проверяет структуру ZIP и контрольные суммы файлов, сохраняет архив целиком, затем вычисляет SHA-256 и размер сохранённого архива и публикует метаданные. Игровые моды хранятся отдельно в `data/mods/`; архивы лаунчера — в `data/launcher/releases/`.

## Контракт API

`POST /api/upload-launcher` — только администратор (Bearer token или действующая cookie). Тело `multipart/form-data`: `launcher` — ZIP, `version` — версия. При успехе `200` и JSON:

```json
{
  "success": true,
  "version": "0.1.1",
  "url": "https://87.58.220.248/download/launcher/0.1.1.zip",
  "sha256": "<64 hex>",
  "size": 28700000
}
```

Ошибки: `400` — неверная версия или ZIP, `401` — нет авторизации, `403` — нет прав администратора, `409` — версия уже сохранена или опубликована, `413` — архив превышает 500 МБ, `500` — ошибка сохранения. Повторная публикация того же номера запрещена, даже если содержимое отличается.

`GET /api/launcher-update?platform=windows-x64` — публичный endpoint. При успехе `200` и JSON с полями `version`, `url`, `sha256` (строка из 64 шестнадцатеричных символов) и `size` (байты). `400` — другая или отсутствующая платформа, `404` — выпуск пока не опубликован. Ответ не кешируется. `url` ведёт на публичный `GET /download/launcher/<version>.zip`. Опубликованные файлы не заменяются, старые URL остаются доступны после выхода новой версии.

`GET /api/client-info` остаётся для старых клиентов. После первой публикации ZIP он возвращает те же метаданные, что и `/api/launcher-update`.

Для резервного копирования включайте `data/launcher/releases/` и базу данных. Версию повышайте для каждого нового выпуска.
