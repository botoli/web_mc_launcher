# Production: 87.58.220.248

Основной сервер 89.125.214.122 и DNS launcher.nevermoreland.ru не изменяются.

## Запуск и доступ

- Основной адрес этой установки: https://87.58.220.248.
- Nginx принимает HTTPS на 443 и прежнем 3443. HTTP на 80 и внешнем 3000 перенаправляется кодом 308 на HTTPS с сохранением метода и пути.
- Express слушает 127.0.0.1:3000, Next.js — 127.0.0.1:3001. На внешнем IP портом 3000 владеет Nginx, а не Express.
- В .env: HOST=127.0.0.1, PUBLIC_URL=https://87.58.220.248, USE_HTTPS=true, HTTPS_ENABLED=false, TRUST_PROXY=loopback.
- В launcher-клиентах и интеграциях следует использовать HTTPS-адрес напрямую: перенаправление не защищает первоначальный HTTP-запрос.

## Runtime и права

Обе службы используют /opt/mc-launcher/runtime/node/bin/node (официальный Node.js 24.22.0, SHA-256 проверен). Системный /usr/bin/node не заменяется, чтобы не затронуть другие приложения. Для npm-команд обслуживания:

```sh
export PATH=/opt/mc-launcher/runtime/node/bin:$PATH
cd /opt/mc-launcher/web_mc_launcher
```

Службы из deploy/ установлены в /etc/systemd/system и включены при загрузке:

- mc-launcher-server: пользователь и группа mc-launcher-api. Код принадлежит root и доступен только для чтения; запись разрешена в data и apps/web/.next/cache. Сертификаты, резервные копии и секреты бота закрыты через systemd.
- mc-launcher-bot: пользователь и группа mc-launcher-bot. Состояние доставки — /var/lib/mc-launcher-bot/delivery-receipts.json, каталог 0700. Запись в исходники запрещена. База и серверный .env недоступны.
- Серверный .env: root:mc-launcher-api, 0640. bot/.env: mc-launcher-bot:mc-launcher-bot, 0600. Ключи сертификатов доступны root, 0600.

Старый bot/.env сохраняет приоритет перед apps/bot/.env. При переезде бота переносите настройки и актуальный файл подтверждений из /var/lib/mc-launcher-bot вместе.

## TLS

Новый независимый ключ и IP-сертификат находятся в /etc/letsencrypt/live/mc-launcher-ip/. Сертификат имеет короткий срок действия около шести дней. Его продлевает актуальный Certbot из /opt/mc-launcher/runtime/certbot, а не системный Certbot 2.x.

mc-launcher-certbot.timer проверяет продление дважды в сутки. Deploy-hook /etc/letsencrypt/renewal-hooks/deploy/mc-launcher-nginx проверяет конфигурацию и перезагружает Nginx после продления. Системный certbot.timer отключён, чтобы старый клиент не обрабатывал IP-сертификат. Порт 80 и каталог /var/www/mc-launcher-acme должны оставаться доступны для HTTP-01.

```sh
systemctl list-timers mc-launcher-certbot.timer
/opt/mc-launcher/runtime/certbot/bin/certbot renew --cert-name mc-launcher-ip --dry-run --run-deploy-hooks --no-random-sleep-on-renew
```

Прежний сертификат launcher.nevermoreland.ru здесь больше не используется. Такой же сертификат обнаружен на основном сервере: сначала замените ключ там, затем отзовите раскрытый сертификат. Отзыв до замены затронет основной сервер.

## Резервирование, проверки и обновление

Перед переключением сохранены unit-файлы, настройки и предыдущая Next.js-сборка в /var/backups/mc-launcher-hardening (0700); создан дамп PostgreSQL в data/backups. Эти копии содержат секреты и должны оставаться закрытыми.

Сборку готовят отдельно от работающего apps/web/.next. После проверки типов, тестов и сборки останавливают бота и сервер, заменяют сборку, запускают службы и проверяют HTTPS /login и /api/status. Не собирайте поверх каталога работающего Next.js.

Для проверки использовалась отдельная временная БД mc_launcher_test с отдельным несуперпользователем; после проверки она удаляется. Всегда задавайте TEST_DATABASE_URL явно. Браузерные тесты используют Chromium через PLAYWRIGHT_BROWSERS_PATH; production-данные не нужны.

## Страницы ошибок

Для неизвестных страниц Next.js показывает 404; ошибки рендеринга, в том числе корневого layout, обрабатываются страницей 500. Если Next.js не отвечает, Express возвращает автономную страницу 503. Nginx показывает автономные страницы для 500, 502, 503 и 504, даже при остановленном приложении. Запросы к API, загрузкам и ресурсам Next.js не перехватываются HTML-страницами.

Проверка без остановки служб: `/errors/404`, `/errors/500`, `/errors/502`, `/errors/503`, `/errors/504`. Эти адреса возвращают соответствующий HTTP-код, не кешируются и не индексируются. Настоящий 404 можно проверить по любому несуществующему пути, например `/this-page-does-not-exist`.

Общий текст, стили и HTML находятся в `apps/shared/error-pages.js`. Команда `node scripts/build-error-pages.js` обновляет `deploy/error-pages/*.html`; она также выполняется при `npm run build`. При обновлении нужно установить новую `deploy/nginx.conf`, проверить `nginx -t` и перезагрузить Nginx.
