# Telegram-вход в Equestrian Dream Launcher

Бот запускается отдельно от веб-панели. Оба процесса **не должны одновременно редактировать users.json**: единственный владелец файла — Express backend. Бот передаёт Telegram updates в его закрытый API через HTTPS и получает команды ответа. Копировать `data/users.json` на хост бота не нужно.

## Веб-сервер

1. Обновите `server.js` и добавьте рядом `telegram-auth.js`.
2. Сгенерируйте общий секрет: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
3. В серверном `.env` задайте `TELEGRAM_BOT_SECRET=<общий секрет>`. Это отдельный секрет, **не токен BotFather**.
4. Запустите обычный `npm start` после сборки сайта. Для API без интерфейса: `node --env-file=.env server.js`.
5. Обеспечьте HTTPS-доступ к API с хоста бота и из лаунчера. Не публикуйте папку `data` как статические файлы.

## Отдельный хост бота

Нужен Node.js 22 или новее. Установка npm-зависимостей для бота не требуется.

1. Создайте бота командой `/newbot` у [BotFather](https://t.me/BotFather).
2. Скопируйте папку `bot/` на другой компьютер или сервер.
3. Скопируйте `.env.example` в `.env` в этой папке и заполните:

   ```dotenv
   telegrambotapi=<токен BotFather>
   AUTH_API_URL=https://ваш-домен
   TELEGRAM_BOT_SECRET=<тот же общий секрет, что на веб-сервере>
   ```

4. Выполните `node bot.js` из папки бота. В репозитории также доступен `npm run start:bot`.
5. Для постоянной работы настройте systemd или другой менеджер процессов на запуск `node /путь/bot/bot.js`. Запускайте один экземпляр.

Имя бота определяется через `getMe` и передаётся backend автоматически. До первого успешного подключения бота API входа возвращает 503. При действующем webhook или конфликте long polling бот останавливается; чужой webhook автоматически не удаляется. Временные ошибки рабочего цикла повторяются; после ошибки первоначального подключения процесс следует перезапустить менеджером процессов. [Официальный Bot API](https://core.telegram.org/bots/api#getupdates).

## Пользовательский сценарий

Лаунчер → «Войти через Telegram» → «Открыть бота» → Start. При первом входе игрок выбирает свободный Minecraft-ник (3–16 латинских букв, цифр или `_`), затем сверяет код и нажимает «Подтвердить вход». Только после подтверждения создаётся `tg_<telegram user.id>` в `data/users.json`:

```json
{
  "tg_123456789": {
    "password": null,
    "email": "",
    "nickname": "NewPlayer",
    "registrationStatus": "pending",
    "registeredAt": 1792000000000,
    "lastLogin": null,
    "token": null,
    "telegramId": "123456789"
  }
}
```

`pending` и `confirmed` разрешены; только `banned` запрещает вход. Старые записи сохраняются; существующий ник не даёт права присвоить чужую запись. Для аккаунтов бота пароль на сайте не создаётся. Привязка существующих веб-аккаунтов, восстановление и установка пароля — отдельные функции.

Повторный вход использует постоянный Telegram user.id, не @username. Блокировка в веб-панели применяется при обмене запроса, проверке сессии и перед запуском игры. Уже запущенная игра не завершается автоматически.

Запрос действует 5 минут. Сессия действует 30 дней без автоматического продления; затем нужен новый вход. Секрет опроса отделён от параметра ссылки, обмен одноразовый. В `data/telegram-auth-state.json` сохраняются хеши секретов и сессий, сроки и offset Telegram; файл нужен для сохранения входа при перезапуске backend. Резервируйте его вместе с `users.json`. Эти файлы не включаются в дистрибутив лаунчера.

В Windows сессия записывается через DPAPI текущего пользователя в `%LOCALAPPDATA%\EquestrianDreamLauncher\state\telegram-session.dat` и привязана к URL backend. Выход удаляет файл и отзывает сессию на сервере. При ошибке сети лаунчер сообщает, что серверный отзыв не подтверждён.

В лаунчере сервер задаётся `LAUNCHER_SERVER_URL`; встроенный адрес по-прежнему HTTP из существующей конфигурации. Для боевого входа задайте HTTPS URL вашего сервера и такой же адрес в `AUTH_API_URL` бота. В worker HTTP разрешён только для localhost при локальной разработке.

## API

| Метод | Путь | Доступ |
|---|---|---|
| POST | `/api/auth/telegram/challenges` | Публичный, ограничен по частоте |
| GET / DELETE | `/api/auth/telegram/challenges/:id` | `X-Poll-Secret` |
| POST | `/api/auth/telegram/challenges/:id/exchange` | `X-Poll-Secret`, однократно |
| GET | `/api/auth/me` | `Authorization: Bearer <opaque session token>` |
| POST | `/api/auth/logout` | Тот же токен сессии |
| POST | `/api/internal/telegram/connect` | `X-Bot-Secret`, имя бота |
| POST | `/api/internal/telegram/update` | `X-Bot-Secret`, Telegram update |

Не передавайте токен BotFather в лаунчер и не размещайте `bot/.env` в публичной папке. Учётная запись лаунчера не заменяет Microsoft/Minecraft-аутентификацию; контроль прямых подключений к игровому серверу требует интеграции с сервером Minecraft.

## Проверки

`npm run test:telegram` выполняет изолированные тесты без настоящего Telegram и без изменения реальной базы. `npm test` дополнительно проверяет существующие API и веб-интерфейс. Для живой проверки нужны заполненные `.env`, доступный HTTPS backend и зарегистрированный бот.
